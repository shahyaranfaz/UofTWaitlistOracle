      HOW THE ORACLE WORKS

      Methodology

      The Oracle estimates whether a particular waitlist rank will clear for a selected U of T lecture. It runs entirely in the browser and is not an official forecast or academic advice.

      Reconstructing waitlists

      The public archive provides enrollment demand, section capacity, capacity changes, and collection timestamps. Queue size is inferred as max(enrollment demand − section capacity, 0). Offerings are aligned by days remaining before the applicable waitlist deadline.

      Defining clearance

      Because students are not identified, clearance is inferred from cumulative observed downward waitlist changes after each snapshot. Capacity increases also advance the queue. Movement occurring entirely between collector snapshots may be missed.

      The model

      Separate regularized logistic models are used for Fall/Winter and Summer. Inputs include rank, queue size, section capacity, capacity-relative ratios, days remaining, recent three- and seven-day movement, capacity changes, course, campus, term, and near-deadline interactions. Lecture selection supplies the live inputs. The lecture number is not itself a predictor.

      Chronological validation

      Each validation session is predicted using only earlier sessions. The primary metric is Brier error, where lower is better.

      The 10% rule assumes a rank will clear when it is no more than 10% of the lecture’s capacity. The historical percentage is how often that same rank cleared in earlier lectures of the course at the same point in the enrollment period.
